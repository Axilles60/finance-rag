# Finance RAG

Решение конкурсной задачи «RAG-ответы по базе знаний». Пайплайн получает вопросы и тексты страниц из CSV, отбирает релевантный контекст и генерирует краткий ответ. Все модели выполняют инференс локально. Результат — CSV с колонками `q_id,answer`.

## Пайплайн

| Этап | Реализация |
| --- | --- |
| Чанкинг | Окно в 1 000 символов, перекрытие в 500. Фрагменты длиной до 30 символов отбрасываются |
| HyDE | T‑Lite формирует гипотетический ответ, который добавляется к запросу для dense-поиска |
| Поиск | Giga Embeddings кодирует чанки и расширенный запрос. PyTorch вычисляет скалярные произведения по всему корпусу. BM25 ищет по исходному вопросу |
| Объединение | Dense и BM25 приводятся к шкале от 0 до 1 отдельно для каждого вопроса. Их взвешенная сумма (`0.7 × dense + 0.3 × BM25`) отбирает 30 кандидатов |
| Реранжирование | BGE оценивает пары «вопрос — чанк». В контекст попадает до пяти лучших фрагментов в пределах 3 200 токенов |
| Генерация | T‑Lite получает вопрос и контекст. Промпт требует краткого ответа по фрагментам и строки «Данных нет» при отсутствии ответа. Лимит — 120 новых токенов |

Модели из финального ноутбука — [Giga Embeddings Instruct](https://huggingface.co/ai-sage/Giga-Embeddings-instruct), [BGE reranker v2 m3](https://huggingface.co/BAAI/bge-reranker-v2-m3) и [T‑Lite‑it‑2.1](https://huggingface.co/t-tech/T-lite-it-2.1).

На конкурсных прогонах увеличение перекрытия до 50% и расширение контекста с трёх до пяти фрагментов улучшали качество. Взвешивание нормированных оценок поиска показало себя лучше RRF. HyDE дал небольшой прирост. Короткий промпт и лимит генерации помогли под метрику Recall‑L, которая штрафует слишком длинные ответы.

## Запуск

Для исходного решения использовалась A100 с 80 ГБ VRAM. Скрипт рассчитан на Linux, Python 3.11 и CUDA GPU с аппаратной поддержкой BF16. Пример установки для CUDA 12.6:

~~~bash
python -m pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cu126
python -m pip install -r requirements.txt
~~~

Поместите CSV из конкурса в `data/` либо укажите пути явно.

| Файл | Обязательные поля |
| --- | --- |
| `questions.csv` | Уникальный `q_id` и текст вопроса `query` |
| `websites.csv` | Текст страницы в `web` или `text` |

~~~bash
python rag.py --questions data/questions.csv --websites data/websites.csv --output submission.csv
~~~

При первом запуске веса загружаются с Hugging Face. По умолчанию используется PyTorch SDPA. Если FlashAttention 2 уже установлен для вашей среды, его можно включить флагом `--attention flash_attention_2`. При нехватке памяти уменьшите размер батча нужного этапа, например `--generation-batch-size 8`. Список параметров доступен через `python rag.py --help`.

Чекпоинты сохраняются в `.rag-cache/`. HyDE и ответы сохраняются после каждого батча, эмбеддинги корпуса — блоками, контексты — после каждого вопроса. Повторный запуск продолжит с сохранённых результатов. Каталог кэша определяется содержимым входных файлов, версией скрипта и выбранным механизмом attention. Для параллельных запусков задавайте разные `--cache-dir`.

Порядок вопросов и значения идентификаторов сохраняются в выходном CSV. Данные конкурса, результаты, чекпоинты и веса моделей хранятся локально.
